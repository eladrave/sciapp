# AI configuration

The administrator manages the active provider, independent conversation/photo model IDs, reasoning effort and the maximum output token limit at `/admin`, Settings, AI models. Changes apply to the next request without a deployment. Configuration is stored in D1 `ai_configuration`; version checks prevent overwriting another administrator's changes.

OpenAI defaults are `gpt-6-luna` for conversation with low reasoning and `gpt-6.1-terra` for photos with medium reasoning. The maximum output is 2,000 tokens including reasoning. There is no automatic escalation to a more expensive model. Model availability depends on the OpenAI project; an unsupported model or effort returns a generic error without changing care records. Future model IDs can be entered directly. Legacy mode keeps the existing Cloudflare Llama conversation and Scout photo models.

The administrator can configure any public HTTPS OpenAI-compatible base URL (including its API prefix), enter a server-encrypted API key, choose Responses or Chat Completions format, and fetch model IDs with Get models. Discovery uses the current unsaved form and calls `<base_url>/models`; it does not activate the provider. Model IDs can always be entered manually, including vendor/model names. Discovery does not guarantee tool or image capabilities. Provider-default reasoning omits the reasoning parameter for compatibility. Nonstandard authentication headers and private/LAN endpoints are not supported. Redirects are rejected and responses are bounded. Keys are encrypted using the existing vault key, bound to their exact base URL, never returned by the admin API, and saved atomically with configuration. Changing the URL requires a new key; the OpenAI secret is used only for the official OpenAI base URL.

The `OPENAI_API_KEY` secret belongs in Cloudflare Workers, `sciapp`, Settings, Variables and Secrets. This legacy environment secret is not stored in D1 or returned by the admin API, exposed to the browser or committed to Git. Replace the secret there, then choose OpenAI and save the AI configuration. Credential ownership and approval requirements are documented in the private Codex Drive knowledge, not in this repository. A rejected credential must not be left installed as an active provider.

Responses-format calls use the Responses API with `store:false`, a 45-second timeout, no redirect following, one tool call per turn and no built-in external tools. Relevant care context, retrieved excerpts and conversation history are sent for conversation; uploaded image data is sent to the selected image model. `store:false` does not imply zero provider retention. Provider failures do not switch silently to a more expensive model. Cloudflare continues to supply embeddings and speech transcription.

The existing backend validates tool intent, parses original medication schedules and requires approval before saving care changes. A new model cannot bypass these controls. Grouped medication schedules merge repeated medication entries and save explicit daily times on approval. As-needed medicines keep their instructions and have no routine dose reminders. Unlisted medicines are not removed automatically.

Deployment requires additive migration `0009_ai_configuration.sql`. Without a saved configuration, OpenAI is selected only when an API key is installed; otherwise legacy Cloudflare remains active. To explicitly keep legacy mode after adding a secret, save Cloudflare in the admin settings before installing the key. Public `/api/health` reports the effective provider and models, never secrets.

Anthropic uses base URL https://api.anthropic.com/v1 with Chat Completions format. Requests to that exact host include its required anthropic-version header (2023-06-01). Use provider-default reasoning. Model and credential ownership are configured separately; the original OpenAI Worker secret is retained for rollback.

Care interpretation, contextual photo reviews, corrections and time resolution are owned by docs/care-agent.md. The active model uses typed tools rather than original-message command parsing; legacy parsers remain only for limited offline controls and older compatibility paths.
